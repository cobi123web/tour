# Production deployment

This project is prepared for a free Render web service with a free external PostgreSQL database.

## 1. Create the database
Create a PostgreSQL database on Neon and copy its connection string (`DATABASE_URL`).

## 2. Put the code in GitHub
Create a GitHub repository and upload the contents of this folder (the repository root should contain `manage.py`, `Trip/`, and `travel/`).

Do **not** commit `db.sqlite3` or `.env` files.

## 3. Deploy to Render
Create a Render Web Service from the GitHub repository, or use the included `render.yaml`.

Set:
- `DATABASE_URL` = your Neon PostgreSQL connection string
- `CSRF_TRUSTED_ORIGINS` = `https://YOUR-SERVICE.onrender.com`

`SECRET_KEY` is generated by Render and `DEBUG=False` is already configured.

## 4. Existing local database
The original local SQLite database is intentionally not deployed because Render free web services have ephemeral filesystems.

If the existing database contains important destinations, tours, reviews, users, or enquiries, migrate that data into PostgreSQL before going live. The safest approach is:
1. Run Django's `dumpdata` against the local SQLite database.
2. Run `migrate` against Neon.
3. Run `loaddata` against Neon.
4. Verify the admin and customer accounts before opening the site publicly.

## 5. Media uploads
The existing `media/` directory is included so the current site images are available on first deployment. Render's free filesystem is not persistent, so new files uploaded through Django admin can disappear after restarts/redeploys. For persistent uploads, connect an object-storage provider such as Cloudinary or S3-compatible storage.

## 6. Security
The supplied README contained a Django admin username/password. Treat those credentials as exposed: create a new admin password for production and do not publish the old credentials.
